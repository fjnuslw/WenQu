# 前端性能优化调研：页面切换卡顿与题库筛选卡顿

> 调研时间：2026-08-29。触发问题：①侧边栏页面切换卡顿；②题库内各筛选选项切换卡顿、每次敲键都闪加载态。
> 结论先行：两个问题分别是「dev 模式按需编译」和「无防抖 + 全量重载」两个经典病灶，均有成熟方案。

## 1. 页面切换卡顿 → 主因：Next dev 模式的按需编译

**现象与共识**：Next.js dev 模式下路由导航慢是长期已知问题——dev 服务器对每条路由做**按需即时编译**（JIT），而生产构建是提前编译好的静态产物；Windows 上杀毒软件实时扫描会进一步放大（官方文档点名）。社区报告 dev 导航 10-20 秒的案例并不罕见。

**来源**：
- Next.js 官方《How to optimize your local development environment》：https://nextjs.org/docs/app/guides/local-development （杀毒软件 / Turbopack / 导入优化 / 依赖项）
- GitHub Discussion: Super slow page load times in development: https://github.com/vercel/next.js/discussions/17977
- Reddit r/nextjs: Is it just me or is Next.js kinda slow during dev?: https://www.reddit.com/r/nextjs/comments/1lprlla/
- DEV: Why is Next.js so slow for developers: https://dev.to/chrismbah/why-is-nextjs-so-slow-for-developers-1gl9

**本项目的决策**：
- 日常使用（备战场景）走**生产模式**：`next build`（一次）+ `next start`——路由预编译 + 无 HMR 开销，切换立竿见影；
- 开发迭代保留 dev 模式（`start.ps1 -Dev`）；
- 补 `(app)/loading.tsx`：即使预加载未命中也立即出骨架，消除"点击后白屏"。

## 2. 筛选切换卡顿 → 主因：无防抖 + 每次筛选全量清屏重载

**现象**：题库页搜索每敲一键就发一次请求；切任何筛选，列表先被清成"加载中…"再重绘（spinner 闪烁）。

**社区标准方案**（TanStack Query 官方 paginated-queries / placeholder-data 指南为代表）：
1. **输入防抖 300ms**：派生 debounced 值，只有它变化才触发请求，避免按键请求风暴；
2. **keepPreviousData**（v5 语义：`placeholderData: keepPreviousData`）：新数据到达前继续展示旧列表，配合 `isPlaceholderData` 把旧列表**降透明度**而不是清空——消除闪烁；
3. 纯客户端大列表过滤另加 `useDeferredValue`（本项目是服务端分页，不适用）。

**来源**：
- TanStack Query 官方 Paginated Queries 指南：https://tanstack.com/query/latest/docs/framework/react/guides/paginated-queries
- TanStack Query Placeholder Data 指南：https://tanstack.com/query/latest/docs/framework/react/guides/placeholder-query-data
- v5 中 keepPreviousData 变更讨论：https://github.com/TanStack/query/discussions/6460
- Stack Overflow: How to use debounce with useQuery: https://stackoverflow.com/questions/76030996/
- useDeferredValue 实践：https://javascript.plainenglish.io/say-goodbye-to-laggy-search-in-react-with-usedeferredvalue-e7cccfae1259

**本项目的决策**：不引入 TanStack Query（当前数据面仅一个列表，引库收益不抵复杂度），**手工实现同等模式**：`useDebouncedValue(value, 300)` 钩子 + 数据与加载态分离（`items/total` 与 `isFetching` 分离，加载中保留旧列表并 `opacity-60` 置灰），与 TanStack Query 的 placeholderData 行为等价。

## 4. 落地清单

1. `start.ps1`：web 默认生产模式（无 BUILD_ID 自动 `next build`），`-Dev` 开关保留 dev；
2. `useDebouncedValue` 钩子 + 题库页数据/加载态分离（keepPreviousData 等价实现）；
3. `(app)/loading.tsx` 路由级骨架；
4. 分类/导入后台守护降速选项：开发调试时可停（已有独立进程，随时可停）。
