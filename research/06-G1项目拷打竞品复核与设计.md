# 06 G1 项目拷打：竞品复核与技术设计（2026-08-29）

> 回答：2026 年了，"读懂你的仓库再拷打你"的竞品出现了吗？G1 第一版怎么落最稳？
> 前置：research/03（agent harness 与 repo 理解四路线，2026-08-28）——本文只做增量复核与工程设计。

## 1. 竞品复核（2026-08-29 检索）

**结论不变且更强：市场空白仍在。** 全网检索（英文/中文）未发现任何"上传 GitHub 仓库/zip → agent 读码 → 针对你的实现深挖拷打"的可产品化竞品：

| 形态 | 代表 | 与本项目差距 |
|---|---|---|
| 简历/JD 驱动 mock | [han-dreamer/ai-mock-interview](https://github.com/han-dreamer/ai-mock-interview)（一面深挖项目/二面扩展）、[interview-skills 网页版](https://github.com/jennifer88huang/interview-skills)、[FoloUp](https://github.com/FoloUp/FoloUp) | 只读简历文本里的项目描述——**候选人说什么它信什么**，无法质证代码 |
| DSA/系统设计 grill | [interviewing.io](https://interviewing.io/)、[Interview Solver](https://interviewsolver.com/)、CodeSignal 等 | 考的是通用算法/设计，不是**你写的那个项目** |
| repo→wiki 理解 | [deepwiki-open](https://github.com/AsyncFuncAI/deepwiki-open)（MIT） | 理解不等于提问——没有面试官策略层、追问链、评分 |
| 语音项目拷打（最近似的开源） | yizucodes/interview-agent（无 license） | 对"项目文档"做 RAG，不是对**代码本身**质证 |

**差异化定位（用户核心思想的产品化表述）**：构建一个**懂项目、懂提问**的 agent——它先像新入职的资深工程师一样把你的仓库读明白（备课），再像最较真的面试官一样对照你的简历声明逐条质证：这个模块怎么实现的？为什么没用 X 方案？为什么没做 Y？同时把**该公司的真实面经追问**和**题库考点**接入提问素材。

## 2. 用户需求 → 设计映射

| 用户要求 | 设计决策 |
|---|---|
| "维护一个临时仓库" | zip 上传 → 解压到 `data/projects/{id}/`（会话级临时区，Zip Slip 防护 + 噪声过滤）；后续支持 git URL |
| "对照简历描述（可选）" | resume_claims（简历画像产出的项目要点"声明"）× 备课产物 → **注水疑点清单**（声明无对应实现/技术词无代码痕迹/指标无法验证） |
| "结合已有的题库内容" | 备课产出的考点（模块技术点）映射题库标签（TAG_FAMILIES）→ 组卷逻辑复用：从题库选相关题作为拷打弹药 |
| "总结出来的经验"（面经） | 该公司面经追问链（experience_items 子节点）注入拷打 prompt 作追问素材 |
| "怎么实现的/为什么不用别的/为什么没实现" | 拷打题型学（§4.3）：实现细节题 / 方案对比题 / 缺失质询题——备课阶段就为每个模块预生成"为什么不 X"的备选方案对照 |
| "深层次拷打" | 两段式（research/03 §3.6）：预计算备课防冷场 + **在线 agentic 读码质证**（面试官当场 read_file/search 代码核对候选人说的和写的一致） |

## 3. G1 第一版架构（本次落地）

```
离线备课（api，每项目一次）                 在线拷打（agents，pi 循环）
┌──────────────────────────┐   ┌────────────────────────────┐
│ zip 上传 → 解压(防ZipSlip) │   │ mode=grill 会话             │
│ → 噪声过滤+语言统计        │   │  system: 拷打官 persona     │
│ → 文件树+重要度排序        │   │  + 备课简报(首轮注入)       │
│ → LLM 备课(分批):          │   │  + 注水疑点+面经追问素材     │
│    模块清单/职责/技术点     │──▶│  窄只读工具面:              │
│    /考点/"为什么不X"备选    │   │   list_files/read_file/    │
│ → (可选)简历声明对照        │   │   search_code              │
│    → 注水疑点清单           │   │  thinking=high 深度推理     │
│ → Project+RepoArtifact 落库│   │  追问链=面试官状态机复用      │
└──────────────────────────┘   └────────────────────────────┘
```

**关键取舍（v1 砍掉了什么，为什么）**：
- tree-sitter 符号图/PageRank 权重 → **v2**：v1 用"README+入口文件+最大源文件"的重要度启发 + LLM 分批备课（备课质量实测够用；tree-sitter 多语言语法包是重依赖，等 v1 验证提问质量后再上）。
- pgvector 语义索引 → **v2**：v1 的 `search_code` 是子串检索（无正则、无索引），对中等仓库足够；Anthropic 立场（活跃代码库向量索引易过期）也支持先用 agentic search。
- git log 归属分析 → **v2**（zip 无 git 历史；等 git URL 通道上线）。
- 评分报告 → **复用 I1**：拷打会话同样落 JSONL，`/api/sessions/{id}/report` 直接可用（报告 prompt 已按"面试记录"通用化）。

## 4. 拷打题型学（备课 prompt 的核心产出物）

每个模块的备课条目必须包含：
1. **职责一句话**（这个文件/模块在干什么）
2. **技术点**（用了什么值得考的库/模式/算法——映射题库标签）
3. **实现细节题**（"X 的 Y 具体怎么实现的？"——答案要点在代码里）
4. **方案对比题**（"为什么用 A 不用 B？"——备课阶段生成 2 个合理替代方案）
5. **缺失质询题**（"这里为什么没做 Z？"——错误处理/测试/并发/降级等常见缺口）

## 5. 安全与合规
- 解压路径监狱（拒绝绝对路径与 `..`）；工具读文件同域名监狱（resolve 后必须仍在项目根内）+ 单文件读取上限。
- 用户上传第三方仓库只做本地分析（spec §10 延续）。
- 工具面刻意排除 write/bash——拷打官只能读不能改（dsh Minimal 模式启发，research/03 §2）。
