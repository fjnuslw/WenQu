## 2. 技术栈盘点（按面试考察层级）

- **RAG 全链路**：文档解析与切分（child/parent、章节结构+字符窗口）、Dense+Lexical 混合召回、RRF、可插拔 Reranker、Metadata（document_id/section_path/source/version）、上下文组装、Golden Cases 评测。
- **Agent 编排**：LangGraph（生成/校验/双级审核工作流、interrupt/resume 中断恢复）、Agent+版本化 Skill+受控 Tool、飞书平台集成（身份/组织/权限/消息）。
- **推理与部署**：vLLM（Qwen-32B）、Xinference（CPU 侧 Embedding/Rerank）、llama.cpp（MiniCPM-V 4.6 Thinking）、SSE 异步任务、FastAPI。
- **多模态 / 观测系统**：全帧 OCR（PP-OCRv6）→ 确定性 ScreenMap → VLM 语义分层观测、跨帧 Evidence Graph（Hungarian 匹配）、SQLite WAL 双账本、版本化 Capsule。
- **检索研究（论文级）**：Embedding 内部注意力利用（IN-Retriever）、Bridge Focus Score、正交投影、HNSW/ChromaDB、优先队列+Beam Search、Agentic RAG 状态机（ESRA: PlanState / EvidenceSpace / Search-Probe-Commit-Write-back）。
- **数据工程**：合成数据集构建（40 OI / 324 Step / 80 媒体证据 / 12 隔离检索任务）、隔离检索任务设计、Excel/ZIP 导出。

## 5. 作为 F4「项目拷打」的首个测试用例

F4 的核心管线是"简历声明 → 代码证据映射 → 注水疑点清单"。用本简历做验收样例：

| 简历声明（claim） | 应在 repo 找到的证据（evidence） | 若缺失 → 疑点 |
|---|---|---|
| "RRF、可插拔 Reranker 及元数据排序" | OpenSOP repo 中 RRF 融合函数、Reranker 抽象接口 | 声明与实现不符 |
| "基于 interrupt / resume 支持审核中断恢复" | LangGraph graph 定义中 interrupt() 调用与 checkpointer 配置 | 只用了框架默认能力却写成设计点 |
| "ownership / epoch fencing 避免错窗" | Local Window Copilot 中 fencing 计数器/世代号逻辑 | 高风险疑点（这是最容易被深挖的词） |
| "Hungarian 匹配构建跨帧 Evidence Graph" | scipy/手写匈牙利算法调用、Graph 数据结构 | 疑点 |
| "SQLite WAL 实现观察与对话双账本" | 建表语句 PRAGMA journal_mode=WAL、两套账本 schema | 低风险（易验证） |

> 结论：本简历的声明密度高、专有名词多，是 F4 注水检测的**高价值试金石**——检测器能对这份简历产出合理疑点清单，才算可用。
