# 05 功能补充与差异化结论

> 在你最初的四点构想（面经搜集 / 厂商题库 / AI 考官 / 项目拷打）之外，基于三路调研补充的功能与定位结论。每条标注优先级与来源依据。

---

## 1. 补充功能清单

### A. 简历工作台（P1，建议新增为独立模块 F5）
- **JD 匹配度分析**：粘贴目标 JD + 简历 → 关键词覆盖缺口、经历与 JD 的映射建议、改写建议。（来源：Final Round AI 验证"基于个人简历的个性化"是付费意愿最强功能；职悟空"简历+JD 追问链路"）
- **简历押题**：上传简历 → 预测提问清单（含追问链、参考答案要点）。（来源：面多多"简历押题"已是成熟功能）
- **简历-题库联动**：解析简历中出现的知识点（如"RRF""vLLM"）自动关联题库对应题目，形成个人刷题清单。（本平台独有组合：F2×F5）
- **简历诊断红线**：量化口径缺失检测（写了"324 个 Step"但没写指标提升就是被拷打点）。（来源：真实面经显示字节从简历深挖）

### B. 学习追踪与间隔重复（P1，新增为 F6）
- **错题本 + SM-2 间隔重复**：刷题答错/面试答差的题进入复习队列。（来源：Anki 工具链成熟、LLM 卡组空白是差异化）
- **掌握度图谱**：按标签体系（RAG/Agent/推理部署…）统计个人强弱项，驱动"今日复习计划"。
- **面试复盘回流**：每次 AI 面试/拷打的失分点自动变成闪卡与模拟题。（闭环：F3/F4 → F6）
- **Anki 导出**：题库一键导出 apkg。（来源：genanki 工具链成熟，LLM 专属卡组市场空白）

### C. 手撕代码专项（P1，并入 F2）
- 大模型岗特有的"手撕 Attention/RoPE/PPO/多跳检索"不是 LeetCode 题，CodeTop 不覆盖（research/02 §3），但对本简历背景是必考项。
- 形态：题库中的"手撕"标签 + 可在编辑器里写+AI 评（MVP 可只做题目+参考实现+自测）。

### D. UGC 面经投稿与爆料（P2，公开化之后）
- 用户投稿面经（公司-岗位-轮次-问题列表）+ 题目爆料（"字节 Agent 岗又被问了 X"），喂频率榜。（来源：CodeTop 爆料机制是其数据护城河；本平台冷启动不依赖它，但远期是壁垒）
- 自用 MVP 阶段以"个人摘录投喂"替代——同一条录入管道，只是来源是手动。

### E. 语音面试（P2）
- LiveKit Agents SDK（Apache-2.0）+ STT/TTS；表达层分析（语速/填充词）是 Yoodli 验证的加分项。（来源：research/03 §4）
- 明确放 P2：文字版先验证追问链与评分质量。

### F. 面试报告与复盘（P1，F3/F4 的一部分但值得单列验收）
- 多维评分报告（理解深度/设计决策质量/代码归属证据/表达/诚实度）+ **证据链**（每条结论引用文件:行号）+ trajectory 回放。（来源：dsh trajectory view；DeepWiki 源码引用范式）
- 报告可分享/导出——远期作为"简历增强物"。（来源：interviewing.io 表现报告可被企业捞人的逆向思路）

### G. 岗位信息聚合（P2，远期）
- 大模型实习/校招岗位聚合（BOSS 标签、DeepSeek 官方招聘、飞书汇总文档）。（来源：research/01 §1a——招聘信息散落，四合一时才做；自用阶段手动维护即可）

### H. 反问环节助手（P1，小功能）
- 面试尾声"你有什么想问的"——根据 JD/公司/面试进程生成反问清单。（低成本高感知，来源：interview-skills 已含 HR 面与谈薪模拟）

## 2. 差异化定位结论（本平台的三个壁垒位）

1. **读码拷打（F4）**：市场完全空白（research/01 §1b），技术有现成积木（research/03 §3），且对"有真实项目的大模型应用候选人"是刚需中的刚需。
2. **大模型版 CodeTop（F2）**：公司×岗位×题目×频率×追问链范式缺位；模型厂商（DeepSeek/Kimi/MiniMax/智谱）专项题库无人做（research/02 §1.5）。
3. **AI 结构化面经管道（F1）**：用 LLM 把散帖自动抽取成结构化数据，区别于牛客依赖人工发帖；面经→题库→模拟面试→复盘全链路数据闭环（牛客/面试鸭各自只有一段）。

**不做的**：不做通用面试工具（竞争红海）；不做企业 B 端（海纳/牛客企业版已成熟）；不碰实时面试辅助（Final Round 路线，争议大且非刚需）。

## 3. 竞争风险与应对

| 风险 | 应对 |
|---|---|
| 牛客/面试鸭复制 AI 模拟面试功能 | 他们缺垂直深度（无读码拷打、无厂商频率榜）；速度+垂直数据是护城河 |
| dsh/pi 生态快速演进使自研 harness 过时 | 采用"瘦 harness+插件"思想而非深度绑定；工具面窄，替换成本低 |
| 无 license 开源仓库的版权争议 | 只取事实性题干、自写答案、公开致谢页（research/02 §5） |
| LLM 结构化抽取质量不稳 | 每批抽取带 schema 校验+抽样人审；Golden Cases 机制自身也用于评测抽取管道 |

## 4. 对"求职者本人"的额外价值（本项目即作品集）

平台本身就是大模型应用开发的完整案例：RAG 管道（F1/F2）、多轮 agent 编排（F3）、代码理解+工具调用 agent（F4）、评测体系（Golden Cases 贯穿）——**求职季结束它就是简历上最有说服力的项目**。开发顺序（数据先行）也保证最短时间内每一层都可单独讲清楚。
